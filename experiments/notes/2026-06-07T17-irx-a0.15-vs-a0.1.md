# irx A=0.15 vs A=0.1 — A optimum is mode-specific

**Date:** 2026-06-07T17 UTC
**Branch:** kannaka-curiosity/2026-06-07T17
**Code changes:** None — env-var only
**Status:** FALSIFIED — A=0.15 worsens irx mode; A=0.1 confirmed irx-specific optimum

---

## Background

Two independently confirmed improvements to L5 fitness:
1. `DREAM_MODE=interference_relax` + `DRIVE_FREQ_HZ=0.5` at `DRIVE_A=0.1`: avg
   fitness 0.099 (T08, PR #157 or similar) — best known L5 result.
2. `DRIVE_A=0.15` at stage_sync: avg fitness 0.132 vs 0.138 at A=0.1 (T21, PR #160).

These two improvements were discovered on separate code paths (irx mode vs stage_sync)
and never combined. The current code default is `DRIVE_A=0.15`. The irx baseline (0.099)
was measured at `DRIVE_A=0.1`, not at the current default.

**Gap:** What is the irx baseline at `DRIVE_A=0.15`? Does the amplitude optimum transfer
from stage_sync to irx mode?

---

## Hypothesis

`DREAM_MODE=interference_relax` at `DRIVE_A=0.15` (current default) improves on the
irx A=0.1 baseline (0.099 avg). Mechanism prediction: the 50% stronger half-cycle arc
pushes carrier_e above 0.940 (near absolute ceiling) and improves transfer_score, with
xi unchanged. Net improvement: ~0.005.

**Alternate prediction:** The stronger drive disrupts the constructive-pair selection
criterion in `stage_interference_relax`, reducing carrier_e and transfer despite more
amplitude energy. A=0.1 remains the irx-specific optimum.

---

## Method

All trials: `DRIVE_A=0.15 DRIVE_SCOPE=all DREAM_MODE=interference_relax`
Default `DRIVE_FREQ_HZ=0.5`, `KURAMOTO_COUPLING=0.5` (bypassed by irx mode).
No code changes.

## Analysis

### A=0.15 worsens both deterministic metrics for irx mode

Transfer and carrier_e are byte-identical across all 3 trials at A=0.15 (fully
deterministic). Compared to A=0.1:

- `carrier_emergence`: 0.935 → **0.803** (−0.132)
- `transfer_score`: 0.836 → **0.820** (−0.016)
- `xi_robustness_v2` avg: 0.559 → **0.588** (+0.029, but with higher variance)

Fitness weight arithmetic:
- carrier_e: −0.132 × 0.10 = **+0.013** fitness penalty
- transfer: −0.016 × 0.15 = **+0.002** fitness penalty
- xi avg: +0.029 × 0.15 = **−0.004** fitness gain
- net: **+0.011 penalty** → predicted avg 0.099 + 0.011 = 0.110 ✓

The data fits the formula cleanly. A=0.15 is definitively worse for irx mode.

### Why A=0.15 hurts irx but helps stage_sync

`stage_interference_relax` drives constructive-pair phase relaxation — it selects pairs
of memories with near-constructive interference and gradually relaxes their phase
separation. Carrier emergence depends on the *relative* amplitude structure being
preserved across the 16-cycle chain so the bimodal carrier signal remains detectable.

At A=0.15, the half-cycle arc imposes stronger amplitude modulation (peak +15% in
cycles 0-8, −15% in cycles 9-16). This increases the amplitude dynamic range, which
disrupts the pair-selection criterion: pairs selected at cycle 0 have a different
amplitude ordering by cycle 8, causing the relaxation to chase a moving target.
The net effect is that the carrier structure built in the first half is partially
undone in the second half — measured as lower carrier_e (0.803 vs 0.935).

`stage_sync` uses Kuramoto coupling, which depends on phase differences, not amplitude
differences. The A=0.15 drive increases amplitude but does not disrupt the phase-based
Kuramoto dynamics — hence carrier_e improves (more signal amplitude to detect) while
the sync structure is preserved.

### xi variance increased at A=0.15

xi range at A=0.1: 0.256–0.874 (range 0.618)
xi range at A=0.15: 0.072–0.921 (range 0.849)

Higher A amplifies the stochasticity of `eval_xi_robustness_v2`, presumably because
the larger amplitude dispersion makes the adversarial perturbation outcome more
sensitive to small initial differences. The single lucky draw (t3: xi=0.921) gave
a record-low single trial at 0.060, but the variance increase makes the 3-trial avg
worse overall.

### Confirmed: best single-trial fitness remains from T08 (0.052)

t1 fitness 0.060 is the second-lowest ever observed, driven by xi=0.921. But 3-trial
average confirms A=0.1 remains the irx operating point.

## Decision

**No code changes to revert.** No improvement. The irx optimum remains:

    DRIVE_A=0.1  DRIVE_FREQ_HZ=0.5  DRIVE_SCOPE=all  DREAM_MODE=interference_relax
    3-run avg fitness ≈ 0.099

The code default `DRIVE_A=0.15` is correct for stage_sync (DREAM_MODE unset) but
must be overridden to `DRIVE_A=0.1` when using interference_relax.

---

## Implications

1. **A optimum is mode-specific.** stage_sync: A=0.15. interference_relax: A=0.1.
   The mechanisms differ (phase-based Kuramoto vs amplitude-based pair selection)
   so the optimal drive strength differs. Future irx experiments should always
   set `DRIVE_A=0.1` explicitly.

2. **The irx 0.099 baseline used A=0.1** — not the code default. Any irx experiment
   relying on default A=0.15 will measure against a suboptimal baseline (0.110).
   Consider adding a code comment or separate L5 path that sets A=0.1 when
   DREAM_MODE=interference_relax is active.

3. **Remaining irx headroom is in xi, not carrier_e or transfer.**
   At A=0.1, carrier_e=0.935 and transfer=0.836 are both near their empirical
   ceilings for the current architecture. The xi avg 0.559 with range 0.256–0.874
   remains the dominant fitness variance source. xi stabilization (seeding the
   adversarial RNG or finding a configuration that raises the xi floor) is the
   highest-leverage remaining direction for irx mode.

4. **carrier_bimodal metric (0.8701)** is now logged separately from carrier_e. Its
   relationship to fitness and whether it can be improved is unexplored.
